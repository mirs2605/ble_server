# コメント規約 (ble_server)

AI・第三者が文脈なしで読めることを目的とする。対象は `ble_server/*.py`、`test/*.py`、`README.md`。

## 1. timeless原則

- コード内コメントに来歴・議論の経緯を書かない（例：「旧〜」「現行」「当面」）。
- 来歴はコミット文・PRに書く。コードには現在の仕様だけ残す。
- 数値の根拠は式・単位で書く。人名・日付・バージョンを書かない（派生ファイルの日付管理は除く）。

## 2. Pythonのdocstring

- モジュールと公開クラス・関数には、責務または入出力の契約をdocstringで書く。
- BLE GATTのサービス、characteristic、UUID、送受信データの責務を明記する。
- JSONからROSメッセージへの変換は、入力形式・座標系・検証失敗時の扱いを明記する。

```python
"""BLEで受信した清掃ゾーンを検証し、ROS 2のPolygonStampedへ変換する。"""
```

## 3. 通常コメント

- 書くのは意図・単位・契約の3点：なぜこうするか、単位、前提条件。
- バイト数・タイムアウト・BLE MTU・QoSには必ず単位・値を付ける（例：`247 bytes`、`5.0s`、`depth 10`）。
- 非同期コールバックには、接続状態・データ完全性・例外処理の意図を書く。

## 4. 禁止事項

- コメントアウトされたコードの放置（不要なら削除し、復元はgitに任せる）。
- 自明な内容の繰返し（コードの朗読）。
- 対話・チャットの文脈を前提にした表現（例：「さっきの」「あの問題」）。

## 5. API文書の生成

Doxygenは未導入である。導入するまでは、READMEのtopic・UUID・データ形式の記述を利用者向け文書の正本とする。
